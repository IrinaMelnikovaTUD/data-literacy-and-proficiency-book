1. The Grammar of Graphics

ggplot2 is based on the (layered) Grammar of Graphics: a graphic is built up from separate layers, and in each layer data is mapped to aesthetic attributes (colour, shape, …) of geometric objects (“geoms”, like points or bars). That is why ggplot2 has no named function like scatterplot() for a specific chart type — any plot is assembled from the same building blocks.

TipSolution

A graphic = data + aesthetic mappings + one or more geoms, stacked as layers. Nothing is drawn until at least one geom layer is added.

2. Advantages and disadvantages of ggplot2

ggplot2 produces high-quality images with sensible design defaults, and its basics are approachable — but fine-tuning takes effort, and it has no support for 3D data (and none is planned).

TipSolution

True: high-quality defaults, approachable basics, effort needed for fine-tuning. False: ggplot2 does not support interactive 3D visualizations.

3. Terminology: data, aesthetics, geoms, facets

  • data always has to be an R data frame.
  • aesthetics map visual properties (colour, shape, size, …) to columns of the data.
  • geoms are the actual geometric objects drawn (points, bars, boxplots, …).
  • facets split the data into panels based on one or two categorical variables.
TipSolution

“facets” = splitting into panels by category. The others are commonly mixed up: aesthetics map properties (they are not the objects themselves), geoms are the objects, and data must be a data frame.

4. facet_grid() vs. facet_wrap()

Both split data into panels by one or two categorical variables. Unlike facet_wrap(), facet_grid(rows ~ cols) lets you explicitly assign one variable to rows and another to columns. facet_wrap() is not restricted to a single row — it wraps panels into a rectangular layout. Faceting by two variables with n and m levels produces n × m panels (not n + m).

TipSolution

True: both facet by category; facet_grid() gives explicit row/column control. False: facet_wrap() can span multiple rows; the panel count is a product, not a sum.

5. geom_bar() position adjustments

position = "stack" (the default) stacks bars, "dodge" places them side by side, and "fill" stacks and rescales to show proportions. "jitter" is not a meaningful position for bars — it is meant for scatterplots.

TipSolution

True: "stack", "dodge", "fill" are real position adjustments for bars. False: "jitter" is not the right tool for bar charts.

6. Wide vs. long format

ggplot2 expects long format: one row per observation, with columns identifying what is measured and which group it belongs to. pivot_longer() converts data from wide to long (not the other way around).

TipSolution

True: ggplot2 wants long format; long format has one row per observation; repeated-measurement data is often collected in wide format. False: pivot_longer() does not turn long data into wide data — that is pivot_wider().

7. Good graphics practices

Focus on the data, remove “chart junk”, use colour-blind-friendly palettes, and make sure a plot stays readable in grayscale — it is not fine for a plot to only work in colour.

TipSolution

True: focus on data, remove chart junk, colour-blind palettes. False: readability should not depend on colour alone.

8. The mandatory argument of ggsave()

Besides the plot itself (which defaults to last_plot()), the file name is the only argument you always have to supply — ggsave() guesses everything else, including the graphic device, from the file extension.

TipSolution

filename — e.g. ggsave("figure.pdf"). Size and device are inferred automatically.
